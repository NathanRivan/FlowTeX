# Product

## Register

product

## Users

Students and academics writing papers, theses, CVs, and other structured documents that need LaTeX-quality typesetting without hand-writing LaTeX. They're mid-task in a writing workflow — drafting, formatting, citing, collaborating with co-authors — not browsing or being sold to. Primary job on any given screen: get back to writing with minimum friction.

## Product Purpose

FlumenWrite (part of the FlowTeX / FlumenWorks product family) is a rich-text document editor that compiles to real LaTeX output. It replaces hand-written LaTeX for people who want typeset-quality documents: academic papers (IEEE/ACM templates), theses, CVs, general long-form writing. Real-time collaboration (Yjs + Supabase Realtime), document sharing (private / link / invite tiers), version history, and LaTeX import/export are core to the workflow. Success looks like: a user can produce a submission-ready document without touching LaTeX source, and can do it alongside co-authors.

## Brand Personality

Precise, calm, unshowy — like a well-made instrument. Trustworthy, quiet confidence. Explicitly NOT: cutesy, gradient-heavy "AI SaaS" startup energy, loud or attention-seeking. The existing visual language (cream/navy, serif brand mark, restrained card grid) already reflects this — extend it, don't fight it.

## Anti-references

Generic AI-SaaS dashboard clichés: gradient-text headers, hero-metric tiles, tiny uppercase tracked eyebrows over every section, numbered 01/02/03 scaffolding, glassmorphism-as-decoration. FlumenWrite is a writing tool, not a marketing funnel — nothing on the dashboard should compete with getting back into a document.

## Design Principles

- Get out of the way — the tool serves the document, never the reverse.
- Consistency with the existing system over novelty; extend the established cream/navy/serif language rather than introducing a new visual dialect.
- Every affordance should read as calm and deliberate, not decorative.
- Organization features (folders, search, sharing) are utilities — quiet by default, clear on demand.

## Accessibility & Inclusion

WCAG AA baseline: ≥4.5:1 body text contrast, full keyboard navigation, visible focus states, `prefers-reduced-motion` support on any animation. No unusual accommodations specified beyond that.
