# Product

## Register

product

## Users

Students, researchers, and technical/academic writers producing LaTeX-grade documents (papers, CVs, reports) without hand-writing LaTeX. They work in long focused sessions inside the Editor (citations, equations, tables, page layout) and manage their work from the FlumenWrite Dashboard (documents, folders, templates, search).

## Product Purpose

FlumenWrite (part of the FlumenWorks family) is a rich hybrid document editor that outputs LaTeX-quality typesetting through a Google-Docs-like WYSIWYG interface: TipTap-based editing, KaTeX math, citation/reference validation, page-accurate layout, and version history. Success looks like a writer never touching raw LaTeX syntax while still getting camera-ready output.

## Brand Personality

Scholarly and refined: precise, calm, editorial. Warm paper tones (off-white backgrounds, navy ink) with an italic serif (Playfair Display) accent on the wordmark against otherwise clean sans-serif UI chrome. Confident and unfussy, not decorative.

Anti-references: generic flat SaaS dashboards, neon/gamer color schemes, glassmorphism-heavy or overly playful UI.

## Design Principles

- Paper-first: surfaces read like paper and ink, not app chrome — the document is the hero, UI recedes.
- Precision over decoration: typographic and spacing precision (this is a typesetting tool) matters more than visual flourish.
- Quiet chrome, loud content: toolbars/menus stay low-contrast and small so page content carries the visual weight.
- Familiar patterns, refined execution: reuse conventions writers already know (Google-Docs-style menubar/toolbar, card-grid dashboard) rather than inventing new interaction models.

## Accessibility & Inclusion

Standard WCAG AA: ≥4.5:1 body text contrast, ≥3:1 for large text/UI components, honor `prefers-reduced-motion`. No colorblind-specific requirements beyond not relying on color alone to convey state (already used for validation markers via icons + color).
